# 0.5.5：本地分支首次发布

问题：Push 必须先有 upstream，而设置 upstream 又只能选择已有的远端分支。新建本地分支因此没有可用的首次推送入口。

交互约定：

- Commit 工具栏显示 `Publish…`，提示本地分支尚无上游。History 的本地分支显示 `No upstream`，右键提供 `Publish Branch…`。
- Fetch 清理已删除的远端引用后，显示 `Remote missing`，允许按原来的远端分支名重新发布。
- 一个远端时直接进入预览；多个远端时先选择目标。预览列出本地分支、远端目标、提交，并说明发布后建立跟踪关系。
- 即使没有新增提交，仍允许创建远端分支。首次发布的文件数是分支当前包含的文件数，提交数相对于该远端已缓存的历史；已有远端分支沿用原来的提交与差异预览。
- 目标同名分支已经存在时，预览改为连接已有分支，遵守原来的 ahead/behind 检查。预览不会提前设置 upstream。
- Commit and Push 先提交选中文件，再进入相同的推送预览。取消发布不撤销本地提交；独立发布的取消保留已有草稿和文件选择。

一致性检查：推送前重新核对本地提交、跟踪配置和远端目标。新分支创建附带“远端引用必须不存在”的条件；预览期间同名分支被创建时，拒绝把发布变成未经预览的更新。

验证：使用临时本地仓库和裸仓库测试首次发布、零新增提交、非当前分支、多远端选择、同名远端分支、远端删除、目标变更和创建竞争；浏览器测试覆盖提示、入口、取消、加载状态及 240px × 420px 的确认按钮可见性。原有搜索、详情、分隔条与焦点回归继续执行。
