# Kivo Git 0.5 — Experience Upgrade

目标：让习惯 IDEA 的用户在 VS Code 中舒服地检查改动、提交、同步和阅读历史。0.5 保持现有 Git 能力范围，逐组件改善日常使用。

信息优先级：**我改了什么 → 我要提交什么 → 操作结果 → 最近提交了什么**。用户主动放大的区域可以优先；默认布局必须服务文件审阅。

## 现有能力与本轮范围

| 已有能力 | 0.5 打磨重点 |
|---|---|
| Changes / Changelists / Diff / Commit | 文件列表空间、文件名可读性、选择反馈、草稿和焦点保留 |
| Push / Pull / Fetch | 入口与计数、菜单边界、确认内容、操作反馈 |
| History / Graph / 文件历史 / Blame | 标题优先、虚拟列表连续滚动、刷新阅读位置、详情 |
| Local / Remote / 分支搜索和切换 | 当前分支上下文、轻背景、懒加载与菜单 |
| 分支对比 / Stashes | 按需打开，滚动内容，稳定底部操作、空状态和重试 |
| 冲突 / 原生 Merge Editor / Continue / Abort | 明确待解决数量，给冲突文件空间，保留恢复与确认流程 |

统计报表、PR 管理、Worktree、交互式 Rebase、AI 功能继续留在后续范围。

## 布局与边界

Commit 自上而下：紧凑仓库/分支头 → 工具栏 → Changes 标题 → **弹性文件树** → Message 握柄 → Message 标题/选择反馈 → 64px 输入框 → 提交操作 → 最近提交。

输入框使用独立高度；按钮不属于可压缩区域。0px 是用户主动收起，不是初始值。窗口变小时仅约束实际显示高度，保留用户选择的高度，窗口变大后恢复；最大尺寸由可用空间决定，并给文件列表留空间。旧版保存的整个提交区高度不直接复用，升级时恢复新默认值，草稿与选择照常保留。

文件列表、Message、Recent、History 和详情各自滚动；不接管滚轮、不加模拟惯性、不对 scrollTop 做缓动。保持 VS Code / 系统原生滚动。

## 实现顺序与发布门槛

1. 重构输入高度模型、默认空间分配和旧状态迁移；实现 01–04。
2. 稳定阅读锚点与 History；实现 05–07。
3. 统一加载、空状态、错误、主题、动画和焦点；实现 08–12。
4. 检查、真实 Git 仓库测试、Webview 交互、扩展宿主和 VSIX 验证通过后交付 0.5.0。

必须复测：240×420、360×820、520×1000 侧栏；宽/窄 History；长文件名、长分支、20+ 文件、长 Message、冲突、Stash、Push 展开；深浅主题和减少动画；两个仓库各自的草稿与布局；迟到响应；分页和刷新。
