# Kivo Git History：布局、字体与色彩规范

适用于 0.6.5 试装版的底部 History 与工作树审阅。设计优先级是：扫读提交、能读全标题、读懂父子关系、辨认当前选择。不要用新的品牌底色覆盖 VS Code 主题。

| 元素 | 决定 | 理由 |
| --- | --- | --- |
| 提交标题 | 列表单行，通常 13px。已识别的合并请求标题用编号短标签；与仓库名完全匹配的重复工单前缀移到元信息，普通标题不改写。截断或简写可悬停、键盘聚焦看原文；详情、查找、复制仍使用原文。 | 列表优先读改动内容，不把长标题误当成多个提交，也不改 Git 数据。 |
| 作者、短 Hash、日期、引用 | 标题下方显示作者与等宽短 Hash，时间靠右，窄栏仍可折行；引用使用安静的小标签。作者旁保留本地首字头像，不请求外部头像服务。44px 是最小行高，不限制下方元信息的折行。 | 标题是第一视觉焦点，元信息可扫读、可核对，不挤占标题。 |
| 分支图 | 保留所有父边和经过该行的线，普通线约 1.5px；检查某条提交时，仅强调相连边，约 2px。 | 车道号不是分支身份，最左边不一定是当前分支。 |
| 图线颜色 | 第五、第六种车道色分别用 `charts.purple`、`charts.orange`；主题未定义时回退到强调色或次要文字色。 | 不在浅色或高对比主题上强行使用固定粉紫色；路径、节点和引用仍是关系依据。 |
| 面板、悬停、选中 | 背景取 `panel.background`；列表状态优先用 `list.hoverBackground`、`list.activeSelectionBackground` 及配套前景色。键盘焦点与鼠标悬停区分。 | 选中表达的是正在检查的提交，不代表已检出该提交。 |
| 工作区操作 | 放顶部，不占据列表左侧整列；常用 Ref 直接可见，作者、日期、路径归入高级筛选。 | 可用宽度首先分配给提交信息，不以隐藏字段换取整齐。 |

## 合入前的检查

- 分别在暗色、浅色和高对比主题检查选中行；作者、Hash、日期必须能读，选中不能只靠车道色辨认。
- 将 History 缩窄到 400px，检查长中文标题、连续英文标识符和长分支名。标题保持单行，鼠标与键盘都能看全文；元信息不遮盖下一条，图线在行边界连续。
- 用有合并提交的历史检查悬停、键盘选择和 `Shift+F10`。菜单出现不应导致标题位移；复制 Hash 应针对选中提交。
- 单独核对 Commit 与 Push：工作区干净不等于已推送，切换上游后不能沿用旧推送成功提示。
