# Kivo Git：Agentic 审阅设计

状态：工作树审阅核心流程已实现，待本地试装。目标用户主要用 AI 或其他外部工具写代码，回到 VS Code 时只想确认：**工作发生在哪里、提交了什么、还有什么没提交**。不要求 agent 接入 Kivo，也不要求用户记住它开的目录。

0.6.4 候选版范围：已注册 worktree 的发现、HEAD 变化与移除；待看计数、按需读取未提交文件、按固定提交查看文件 Diff、手动标记已查看。未提交文件仅在打开或刷新目标审阅时读取，不产生逐文件后台提醒。

后续任务与验收见 [0.6.5 Agent 交付审阅路线图](./AGENTIC_REVIEW_ROADMAP.md)。提交分页与独立目标分支比较在 0.6.5 的 P0 试装版中验证。

## 现状与缺口

当前快照已读取同一 Git 仓库的已注册 worktree，History 顶部也有 Worktrees 管理入口。问题是这个入口要求用户先知道要去点它；当前目录的变更文件监听也不能覆盖所有外部 worktree。Kivo 要把「发现、查看、审阅」放在「创建、删除、打开」之前。

## P0：发现与审阅，同一版交付

### 1. Worktree 发现

- Commit 仓库区和 History 现有 Worktrees 按钮共享同一个入口与同一份状态。没有其他 worktree 时保留普通入口；有变化时写明 `Worktrees 3 · 1 个待看`，不用只靠颜色或闪烁来提示。这里的 `3` 是仓库内可读的已注册工作区数量，包含当前工作区；不可用条目另外标注。提示不盖住提交消息，不打开新窗口，不抢焦点。
- 仅发现当前仓库共同 Git 目录下注册的 worktree，不扫描磁盘、不猜测 AI 厂牌。按共同 Git 目录隔离状态，并在列表里按 worktree 注册身份区分条目；显示当前、其他、分离 HEAD、锁定及不可用等不同状态。锁定不等于无法读取。删除后重建且身份已变化的同路径条目按新 worktree 处理。
- 没有本地记录时，已有 worktree 显示为「已发现」，不冒充刚创建。按仓库在本地持久化最近一次成功快照和已查看检查点；比较成功快照，识别新出现、HEAD 或分支变化、消失的条目。被移除的条目保留为待看的记录，直到用户确认；读取失败显示「状态未更新」，不能报成「已移除」。`待看` 计有未确认变化的 worktree，不计命令、事件或提交次数。
- 切入窗口、打开面板时做轻量刷新；优先监听共同 Git 目录下的 worktree 注册与相关引用变动，视图可见时用低频轮询兜底。监听事件合并，扫描有并发上限，不在每次按键时跑所有工作区的 `git status`。VS Code 关闭期间只可比较前后状态，不能承诺还原完整事件序列或精确发生时间。

### 2. 看清「提交了哪些」

- 点击入口在现有 History 打开审阅视图，把当前与其他 worktree 分组；优先显示待看项。每项先显示分支、路径、最新提交；选中后看提交列表和文件 Diff。未提交变更与提交列表分开，按需读取，不能用当前 worktree 的工作区状态替代目标的状态。未检查时显示「尚未检查」，不显示 `0`。
- 默认有可用历史检查点时显示「自上次标记已查看」，比较当时保存的 HEAD 与当前 HEAD。首次没有检查点时显示近期提交，不标成「新增」或「AI 提交」。另提供显式「相对目标分支」比较，以选定目标与该 worktree HEAD 的共同祖先和固定 OID 为依据；目标不可用或无共同祖先时说明，不猜 `main`。未推送状态独立表达，不把未审阅、未推送、未合入合并成同一个数字。
- 通过「标记已查看」才推进检查点，绑定当次审阅的确切 HEAD；阅读期间来的更新继续待看。遇到 rebase/reset、旧检查点不可达或对象缺失时，显式显示「历史已改写 / 旧基准不可用」，不把现有全量历史标为新增。
- 不改变当前检出、Commit 选中文件、草稿或 History 普通浏览状态。已提交内容的 Diff 固定到正在审阅的 Git 对象；目标 worktree 已删除时，仍可读可解析的提交对象，但不能打开其工作区文件。退出后回到原选中行和焦点。

## P1：审阅效率

- 按待看项连续审阅，支持按文件或提交切换；标题、作者、短 Hash、日期保留。复用 History 现有换行、主题 token 和原生 Diff。计数与状态用文字加图标，浅色、暗色、高对比主题一致。
- 提供「复制审阅范围」：工作区、分支、起止 OID 和文件清单，方便交回给任意 agent；不自动发送，不把代码或路径上传服务。路径仅用于本地界面及用户主动复制。

## 本期不做

不引入新的 Activity Bar 页面，不做 AI 聊天、Agent 管控、强制预提交 hook 或自动 commit/push/merge/清理。Git 作者、分支名、目录名都不能证明是谁建的 worktree 或写的代码；界面用「在插件外观察到的变化」，不用「AI 创建」。不同 clone 或未注册的任务副本不在发现范围内。后续如需任务来源，可另加显式、可选的 agent 标签，不阻塞 P0。

## 验收

1. 用终端在 VS Code 工作目录之外创建同仓库的 linked worktree 并提交，再回到 VS Code：刷新后有待看提示，点进去无需切分支即可看到对应提交和真实 Diff。
2. 同一目标既有未提交修改又有已提交记录：两组分别显示；推送后只更新推送状态，待看状态保持到显式标记已查看。
3. 已查看后目标新增提交、rebase 或删掉 worktree：提示对应变化，不串到其他仓库，不把读取失败当删除，不改当前草稿。
4. 兼顾从主工作区与 linked worktree 打开同一仓库、分离 HEAD、带空格路径，以及中文／英文、窄栏和键盘操作。
